# design-sync notes — Smarter Dog UI Kit

## Repo shape

This is not a published component library. `src/components/ui/` is an internal
UI-kit folder inside the main booking app (`smarter-dogs-smart-humans`), no
`package.json`/`dist`/`.d.ts` of its own. Synced via the **package** shape in
synth-entry mode, with every component pinned explicitly in
`cfg.componentSrcMap` (bypasses the empty-`.d.ts` problem — `exportedNames()`
has nothing to read since there's no shipped `.d.ts` tree). 26 components,
scoped to exactly the barrel exports in `src/components/ui/index.js` (not
every file in the folder — `ErrorBoundary`, `PageShell`, `NetworkOfflineBanner`,
`OfflineDemoBanner`, `ScribbleUnderline` live in the same directory but aren't
barrel-exported and were deliberately left out of this sync's scope).

## cssEntry: hand-built, not auto-derived

`cfg.cssEntry` (`.design-sync/.cache/compiled-tailwind.css`) is **not**
regenerated by the converter — it's a manually built file because this app
uses Tailwind v4's CSS-first `@theme` config (`src/index.css`), so classes
like `bg-brand-yellow` don't exist as real CSS until Tailwind compiles them.
To rebuild it on a future re-sync:

```sh
npm run build   # produces dist/assets/*.css (the compiled Tailwind output)
cat dist/assets/index-*.css dist/assets/skeleton-*.css dist/assets/CustomerApp-*.css \
  > .design-sync/.cache/compiled-tailwind.css
```

Then **strip noise** that leaks in from concatenating the whole app's CSS
(these two families/rules are confirmed NOT used by any of the 26 synced
components — verified via `grep` of `src/components/ui/*.jsx`):
- Any `.font-\[...\]{font-family:...}` rule mentioning `DM Sans` or `Sora`
  (arbitrary-value Tailwind classes used elsewhere in the app, unrelated to
  this component set).
- Rewrite `url(/fonts/montserrat-*.woff2)` / `url(/fonts/quicksand-*.woff2)`
  → `url(../../public/fonts/montserrat-*.woff2)` / `../../public/fonts/quicksand-*.woff2`
  (the compiled CSS ships web-root-absolute paths; the converter resolves
  font `url()`s filesystem-relative to `cssEntry`'s own directory, so the
  absolute form always reads as dangling).
- Drop the 4 Caveat cyrillic/latin subset `@font-face` blocks (Caveat is
  wired properly via `cfg.extraFonts` → `@fontsource/caveat/700.css` instead —
  see below — these subset blocks are the app's *build output* copies, not
  needed since extraFonts sources the real fontsource package directly).

If this isn't redone before rebuilding, the previous manually-cleaned
`compiled-tailwind.css` is just reused as-is (it's a committed file, not
gitignored) — only redo this if the app's Tailwind output has actually
changed (new brand colours, new fonts).

## Fonts

- **Montserrat / Quicksand** (`--font-sans` / `--font-display`) are the
  app's real body/heading fonts — wired via the cssEntry fix above, files
  live in `public/fonts/`.
- **Caveat** (`--font-handwriting`) isn't used by any of the 26 synced
  components directly, but it's a real, intentional brand token (not noise
  like DM Sans/Sora), so it's wired via `cfg.extraFonts: ["node_modules/@fontsource/caveat/700.css"]`
  rather than deleted.
- **DM Sans, Sora**: confirmed NOT part of this design system's real font
  vocabulary — one-off arbitrary-value Tailwind classes used somewhere else
  in the app (not in `src/components/ui/`). Stripped from cssEntry, not
  wired up. If a future re-sync reintroduces this warning, re-verify with
  `grep -rn "DM Sans\|Sora" src/components/ui/*.jsx` before assuming it
  needs fixing — if that grep is still empty, it's noise again.

## Known render warns (triaged, safe to ignore on re-sync)

- `[RENDER_ERRORS]` on **ErrorBanner** and **InlineError**: false positive.
  `package-validate.mjs`'s render check treats any mount whose `textContent`
  starts with "⚠" as a caught render error (`t.startsWith('⚠')` at
  `lib/../package-validate.mjs` render-check block) — but both components
  legitimately render a real "⚠"/"⚠️" warning glyph as their OWN first
  character of content (that's their actual UI, not a thrown error). The
  "error text" printed is just their own message with the glyph sliced off
  (confirmed by manually loading the page with `page.on('pageerror', ...)` —
  no real error fires; the glyph-prefix heuristic is the whole story).
  Not a bug in these components — don't try to "fix" it by removing the
  glyph or changing markup.

## Grouping

No real component docs exist, so every component's `<group>` comes from a
`cfg.docsMap` stub (`.design-sync/docs-stubs/<Name>.md`, just
`---\ncategory: <group>\n---`) rather than discovered docs. Groups used:
`actions`, `surfaces`, `status`, `feedback`, `layout`, `data`, `loading`.

## Authored-preview constraint: cssEntry only has classes the real app already uses

`cssEntry` is `dist/`'s compiled Tailwind output (see above) — it contains
**only the utility classes some real app page already triggers**, not the
full Tailwind utility set. A `.design-sync/previews/<Name>.tsx` wrapper `div`
that reaches for a class no real app page happens to use (e.g. `h-24` — not
used anywhere in this app today) silently renders with NO height, since the
class doesn't exist in the shipped CSS at all (caught this in `SkeletonBlock`'s
`Shapes` story — fixed by using an inline `style={{ height: 96 }}` instead).
**When writing wrapper markup in a preview, prefer inline `style` for any
arbitrary/uncommon sizing** rather than a Tailwind class you haven't verified
is already in `ds-bundle/_ds_bundle.css` — classes passed as real component
*props* (e.g. `variant="primary"` on `Button`) are safe, since those are
hardcoded literals inside the component's own source and guaranteed to be
compiled (the component is used somewhere in the real app). Verify any new
wrapper class with: `grep -o '\.<class-escaped>{[^}]*}' ds-bundle/_ds_bundle.css`
(escape `/` as `\/`, `.` as `\.` etc. — Tailwind escapes special chars in
selectors).

## guidelinesGlob deliberately empty

The default `guidelinesGlob` (`docs/*.md`, `docs/guides/**/*.md`) matches
against `PKG_DIR` — which is the **whole app's repo root** here (no separate
package dir), so it picked up the entire `docs/` folder: capacity-engine,
migrations, whatsapp-agent, staff-web-push, etc. Those are the booking app's
internal engineering docs, not design guidance for this UI kit, and some
touch security-sensitive internals — irrelevant/inappropriate to ship into a
design system a design agent reads for building UI. Set to `[]` deliberately.
This kit has no real design-guideline docs of its own; if one gets written
later (e.g. a proper `docs/design-system/*.md`), point `guidelinesGlob` at
that specific path rather than re-widening it to the repo default.

## Re-sync risks

- The cssEntry rebuild above is **manual, not automated** — a future sync
  that just runs `resync.mjs` without redoing it will silently reuse the
  last-cleaned CSS snapshot (stale but not wrong, since nothing in the 26
  components' own Tailwind class usage is likely to change often — check
  git blame on `src/components/ui/*.jsx` and `src/index.css`'s `@theme`
  block since the last sync before trusting the cached CSS).
  Provisioning that step in a proper `cfg.buildCmd`/script would remove this
  risk — not done here for time.
- `componentSrcMap`/`docsMap` enumerate every component by name (not the
  usual "exceptions only" sparse pattern) because there's no `.d.ts` and no
  real docs at all — this is correct for this repo's shape but will need a
  new entry by hand whenever a component is added to or removed from the
  `src/components/ui/index.js` barrel.
- `Button` and `PageHeader` are pinned to `cardMode: "column"` in
  `cfg.overrides` (their multi-story exports render wider than a grid cell).
