# Implementation plans

Implementation plans explain **how** an approved change will be delivered.
They are not product specifications and they are not live task boards.

- [`active/`](active/) contains plans whose implementation or verification is
  not complete.
- [`completed/`](completed/) contains the plan as it stood when the linked work
  was verified. Completion notes may be appended; historical steps must not be
  rewritten.
- [`../archive/superpowers/plans/`](../archive/superpowers/plans/) preserves the
  earlier planning convention. Existing links remain valid; files are moved
  only as part of an explicit documentation-maintenance change.
- [`../superpowers/plans/`](../superpowers/plans/) contains legacy active-path
  plans and a small amount of implemented work awaiting classification. Check
  each document's own status before acting.

All new substantial plans follow [`.agent/PLANS.md`](../../.agent/PLANS.md),
live under `docs/plans/active/`, and link to a GitHub issue.
